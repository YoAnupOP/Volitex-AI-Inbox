## Traefik gate: verified configuration, pending server application

The [compression gate report](n8n-compression-gate-2026-10-14.md), `deployment/n8n/traefik-compression-guard.yaml`, and n8n-main's `coolify.traefik.middlewares=volitex-n8n-identity@file` label remain present. The recorded isolated test proves zero new native compressor allocations through the guarded proxy, including bounded disconnects. No image dependency was patched.

Install the YAML in **Coolify → Servers → target server → Proxy → Dynamic Configurations → Add**, using the file's exact content. Save it, check provider logs, then deploy the Compose resource. Inspect the **running** n8n main container's generated `traefik.http.routers.*.middlewares` labels: every router forwarding to n8n must reference `volitex-n8n-identity@file`. A source shorthand label alone is not evidence of generated router attachment. HTTP routes may redirect without reaching n8n; any HTTP route that does forward must also be guarded.

The Compose file has no host port mappings for n8n, its worker, PostgreSQL or Valkey; only main's container port is exposed for the proxy. Do not assign public domains to the other services, add host port mappings or alternate unguarded routers. Keep n8n administration restricted to trusted operators; retain authenticated HMAC webhook validation.

**Not production-tested:** generated Coolify routers, public port isolation, HTTPS/TLS, authenticated editor/API requests and a valid signed workflow execution through the deployed guard. Before client acceptance, inspect the generated labels/routes and host bindings, verify a normal TLS connection and login, send harmless gzip/br/deflate negotiation requests to the n8n route, and execute the existing authorized synthetic HMAC workflow. Confirm the backend receives identity encoding, the signature succeeds, the reply targets the expected tenant and no alternate direct port is reachable. A response may be compressed by Traefik itself; inspect the backend hop to prove n8n is not compressing. Do not weaken or remove the guard to recover a broken route: keep ingress private until configuration is corrected.

Docker Desktop's engine pipe was unavailable during this task. The existing Docker-based compression test was therefore not rerun. Prior isolated HTTP root/API-denial/missing-webhook evidence is not an authenticated HTTPS acceptance test. No production deployment or route change occurred.

### Minimum bulk implementation before enablement

Add a tenant-bound recipient snapshot/ledger with a unique campaign/contact delivery identity, attempts, provider ID, suppression/eligibility result, terminal/unknown states and visible failure counts. Atomically claim bounded batches with a recovery lease; define safe pause/cancel boundaries and resume only unfinished recipients. Preserve an accepted send's identity before retry/reconciliation, and explicitly handle an ambiguous provider timeout rather than claiming exactly-once delivery. Add bounded rate/backoff behavior and monotonic, deduplicated status reconciliation. Enforce approved templates and consent/suppression server-side, remove recipient PII from routine campaign logs, and add the missing failure/recovery/isolation tests. This is a coherent campaign subsystem change requiring explicit state/API design, not a low-risk visual patch; it was not partially improvised here.

## First-client deployment gates

1. 3. Before public n8n traffic: install and verify the Traefik middleware and generated routes described above; verify TLS and absence of bypass ports. Preserve the trusted-operator editor policy and existing tenant-bound AgentBot/HMAC credentials.
4. Back up before `RAILS_ENV=production bundle exec rails db:chatwoot_prepare`; confirm migration/readiness. Preserve encryption keys. Across data migrations, rollback requires the matching database/media backup and compatible image; do not image-downgrade blindly.
5. On KVM 4, prove off-server encrypted backup restoration to a disposable destination, controlled reboot recovery, background queues, storage persistence and alert delivery to an operator. Record measured recovery time/RPO; documentation and local restore tests do not satisfy this server gate.
6. Configure each client's real business workflow, Meta asset/channel and consent expectations; test WhatsApp and Instagram if sold, one inbound/reply, signed webhook, ownership takeover, duplicate and tenant isolation. Existing live WhatsApp evidence covers the staging test workflow, not every client's channel or business logic.

Recommended after acceptance: tune worker concurrency from measured initial load and alert history; keep medium/low advisory dispositions and baseline-suite debt tracked without reopening this release scope. Accepted architectural risk: a single VPS is a shared failure domain, with no cross-host automatic failover; capacity and recovery are bounded by measurements, not zero-downtime promises. Campaigns remain disabled until their separate gates pass.
